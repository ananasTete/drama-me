
### 为什么节点接口要设计为 batch 批量操作接口？

1. 一个用户动作经常影响多个对象，比如：
  1. 删除节点 A，那还要删除 A 和 B 关联的连线
  2. 鼠标选择区域，拖拽移动全部节点
2. 减少高频请求，画布交互非常密集。批量操作可以把短时间内的变更合并

### 为什么要设计 mutationId 字段？

mutationId 是“一次写入请求的唯一编号”，最典型的问题是：服务端成功了，但客户端没有收到响应，比如网络在返回响应时断了。客户端看到的只是：请求失败或超时它不知道服务端是否成功。tansatck query 客户端会尝试重试, 但此时服务端已经是 revision + 1，会返回冲突。客户端无法直接区分：是别人修改了画布；还是自己上一次请求已经成功，只是响应丢了。如果是前者返回异常是对的；如果是后者应该返回第一次成功的响应。加上 mutationId 之后，有了双重判断标准，mutationId 与响应会在数据库单独表存储，当 reversion 冲突但 mutationId 是最新记录时，就代表执行过，就不再重复修改数据库，直接返回第一次保存的结果。这也要求在 tanstack query 重试时发送相同的  mutationId。

### 撤销操作是客户端发送反向操作

原操作：

```ts
{
  type: "node.create",
  node: createdNode,
}
```

撤销：

```ts
{
  type: "node.delete",
  nodeId: createdNode.id,
}
```
